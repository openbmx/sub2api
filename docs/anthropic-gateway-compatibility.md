# Claude 转发兼容说明

Claude Messages、Chat Completions、Responses 和 token 计数使用同一组输入转换规则。账号配置中的透传和禁用选项仍决定是否执行对应改写。

- 上游返回 `x-should-retry: false` 时，当前请求停止内部重试及账号切换，客户端收到对应状态、原因和重试指示。正常配额、过载及凭据恢复继续按原有规则处理。
- Claude 授权、交换及刷新已指定代理时，代理解析失败会返回错误。未指定代理的请求继续使用默认网络配置。刷新成功但凭据保存失败时，本次刷新不重复提交旧凭据。
- 刷新成功只解除 Claude 认证或刷新失败造成的临时停调。usage 查询成功不解除刷新凭据错误；验证成功并保存的新凭据可以恢复相应认证错误，额度及人工暂停保留。
- 开启指纹统一时，原生和模拟请求使用同一账号画像。软件升级保留已知 OS/架构；实际客户端版本与配置版本下限分别记录，新建画像记录的实际客户端版本可用于识别后续 SDK 更新，存量出站版本继续只升不降。缺少目标 `account_uuid` 不影响已知 device/session 的重写。
- Messages、Chat Completions 和 Responses 使用下游客户端上下文区分合成 session，并在追加消息时保持稳定。session masking 开启时，通过 Redis 原子初始化取得账号共享值并续期；必要缓存失败会阻止出站。显式 metadata 透传配置继续生效。
- 工具名只在本次账号尝试的协议字段中改写与还原，包括工具调用、搜索引用、addition/removal 及 inline 定义。正文、代码、工具参数和 ID 保持原文；换号清除前一次映射。
- 显式账号模型映射在调度和各转发入口一致生效，并在模型能力校验前解析。空映射保留原有模型范围。已知 Claude 模型使用相应 thinking 模式；生成的手动预算遵守调用者显式输出上限，无法容纳最低预算时返回请求错误。
- 原生 Messages 的手动 interleaved thinking 参数继续按其协议发送。Responses/Chat 转换的预算和 adaptive 模式由最终模型决定；未知第三方模型保留原有转换行为。
- 第三方 OAuth 的 system 迁移保留附加规则、文本块边界和缓存 TTL，并去掉重复独立身份 banner。token 计数使用同一提示词变换，之后过滤计数端点不接受的生成字段。
- 缓存上限计算顶层自动缓存实际占用的断点；末块已有断点时复用，并保持 TTL 一致。仍按工具、消息、system 的既有优先级移除超额断点，延迟加载工具上的非法缓存标记会先清除。
- `safeguards` 与配套 beta 一起保留。最终账号或管理员配置不允许该 beta 时，在出站前明确返回请求错误，保留审核能力的选择权。
- 官方 Anthropic 和 Claude Platform on AWS 目标转发功能请求头，账号凭据替换和头覆写规则继续生效。`x-should-retry` 响应头遵守现有响应过滤配置；显式 `force_remove` 优先。
- 日期规范化只处理独立环境日期行，保留行内引用、逐字模板和围栏代码。开关及适用账号范围保持原配置。
- Vertex service account 的 `count_tokens` 在参数校验后返回 404，客户端可使用本地估算；不会获取 Google token 或向 Anthropic 发送该凭据。

## TLS 模板

TLS 指纹在 Anthropic OAuth/setup-token 的账号编辑页开启，模板通过管理界面持久化。未开启时使用普通传输；开启后可选择内置默认或固定模板，`-1` 表示每次解析随机选模板。同一账号需要固定画像时使用固定模板。

TLS 客户端按账号、代理及有效模板内容隔离。HTTP、HTTPS CONNECT 和 SOCKS5 均使用选定的目标 TLS 模板；HTTPS 代理先独立验证代理 TLS，再建立目标隧道。指纹传输使用 HTTP/1.1，保存及运行时拒绝包含 `h2`/`h2c` 的模板。

TCP、代理握手及目标 TLS 建连受 30 秒上限和请求取消约束。成功建立的复用连接不会因为已完成请求的取消而关闭；证书校验保持启用。

## 已知限制

这些规则保证已覆盖协议和配置的行为一致性。官方客户端的 TLS/HTTP/SDK 值是否匹配，需要按具体版本和平台对照；当前未据此承诺账号不会被供应商停用。

成功刷新后遇到持久化故障，当前进程会保留该账号最近一次交换结果用于重试保存。该恢复信息不跨进程或重启共享；持续数据库故障应先恢复存储，必要时重新授权，不能依赖反复刷新恢复。

system 迁移保留文本，但会把原 system 放入合成 user 消息，改变其角色层级。工具别名不会替换自然语言中的工具名称。没有显式会话标识时，相同下游客户端以相同首句开启的独立对话仍可能使用相同合成 session。

上游配额响应头表示产生该响应的上游账号窗口，不代表网关账号池总额度。需要额外配额头时，可使用现有 `security.response_headers.additional_allowed` 配置逐个放行。
